# MedoEDUz как Telegram Mini App + синхронизация прогресса

Пошаговая инструкция для владельца проекта. Всё делается один раз.
Ничего в коде менять не нужно — только вставить два значения после деплоя.

---

## Часть 1. Открыть приложение как Mini App (без синхронизации)

Этого достаточно, чтобы приложение открывалось внутри Telegram, брало
имя пользователя и работало с нативной темой и хаптикой. Прогресс при
этом хранится локально на устройстве.

### Какой адрес указывать

Экранов два, и они дополняют друг друга (прогресс общий):

| Адрес | Что это |
|---|---|
| `.../MedoEDUz/app/learn.html` | **Учебная сессия — основной экран.** Повторение, изучение, практика, проверка с оценкой уверенности, рефлексия, дневник. Указывайте его. |
| `.../MedoEDUz/app/` | Карта знаний и эволюция маскота. Дополнение к сессии. |

### Шаги

1. Откройте [@BotFather](https://t.me/BotFather).
2. Если бота ещё нет: `/newbot` → задайте имя и username.
3. `/newapp` → выберите бота → заполните:
   - **Title:** MedoEDUz
   - **Description:** Учебные сессии по работе с ИИ: практика, проверка, рефлексия
   - **Photo/GIF:** любая обложка 640×360
   - **Web App URL:** `https://demodaygit.github.io/MedoEDUz/app/learn.html`
   - **Short name:** `learn` (адрес станет `t.me/ваш_бот/learn`)
4. Кнопка меню бота: `/setmenubutton` → выберите бота → тот же URL
   `https://demodaygit.github.io/MedoEDUz/app/learn.html` → текст «Учиться».

Готово. Приложение открывается в Telegram.

### Что проверить сразу (вкладка «Профиль» → «Диагностика»)

Страница сама показывает своё состояние — открывать консоль не нужно:

- **Модель курса** — «49 узлов, 98 вопросов». Если пусто, не подгрузился
  `data/curriculum.js`.
- **Telegram** — «вход как <ваше имя>». Если «вне Telegram» — вы открыли
  адрес в обычном браузере, это тоже рабочий режим.
- **Локальное хранилище** — «работает». Если нет, браузер запретил
  localStorage (режим инкогнито с жёсткими настройками).
- **Синхронизация** — «выключена (локальный режим)», пока не сделана часть 2.
- **Офлайн-режим** — «кэш активен» после второго открытия.

Плюс живая проверка: пройдите одну сессию до конца. Должны сработать
шкала уверенности, разбор ответа, четыре вопроса рефлексии, начисление XP
и дата следующего повторения. Кнопка «Дневник .md» выгружает всё
написанное вами файлом — это самый быстрый способ убедиться, что данные
реально сохраняются.

> Карта знаний сайта тоже работает как Mini App по адресу
> `https://demodaygit.github.io/MedoEDUz/pages/roadmap.html`.

## Часть 2. Синхронизация прогресса по Telegram ID (опционально)

Чтобы прогресс переносился между устройствами и не терялся при
переустановке — нужен лёгкий бэкенд. Мы используем Cloudflare Worker
(бесплатный тариф покрывает нужды с запасом).

### 2.1. Установить инструменты

```bash
cd worker
npm install -g wrangler   # CLI Cloudflare
wrangler login            # откроет браузер, войдите в Cloudflare
```

### 2.2. Создать хранилище прогресса

```bash
npx wrangler kv namespace create PROGRESS
```

Команда выведет `id = "..."`. Вставьте его в `worker/wrangler.toml`
вместо `ЗАМЕНИТЬ_НА_ID_ПОСЛЕ_СОЗДАНИЯ`.

### 2.3. Положить bot-токен в секреты

```bash
npx wrangler secret put BOT_TOKEN
# вставьте токен бота из BotFather — он НЕ попадёт в репозиторий
```

Токен нужен воркеру, чтобы проверять подпись Telegram и убеждаться,
что запрос действительно от вашего пользователя, а user_id не подделан.

### 2.4. Развернуть

```bash
npx wrangler deploy
```

Вы получите адрес вида `https://medoeduz-sync.ВАШ.workers.dev`.

### 2.5. Включить синхронизацию — ОДНА строка

В файле `js/config.js` (единая точка настройки) вставьте адрес воркера:

```js
window.MEDOEDUZ_SYNC_URL = 'https://medoeduz-sync.ВАШ.workers.dev';
```

Затем синхронизируйте копию в приложение и запушьте:

```bash
bash build-app.sh          # копирует config.js в app/
git add -A && git commit -m "enable sync" && git push origin main
```

GitHub Pages опубликует автоматически. С этого момента прогресс
синхронизируется по Telegram user_id между всеми устройствами.

> Если оставить URL пустым — синхронизация просто выключена,
> приложение работает локально. Это безопасное значение по умолчанию.

## Как это работает и почему безопасно

- Приложение **никогда не ждёт сеть**: всё пишется в localStorage мгновенно,
  синхронизация — фоновая с дебаунсом 3 секунды.
- Каждый запрос к воркеру несёт подписанную Telegram строку `initData`.
  Воркер проверяет её HMAC-SHA256 подписью bot-токена — **подделать
  user_id без токена невозможно** (проверено: подмена id ломает подпись).
- Bot-токен лежит только в секретах Cloudflare, никогда не в браузере
  и не в репозитории.
- Проверяется срок: `initData` старше 24 часов отклоняется.
- CORS разрешён только для `https://demodaygit.github.io`.
- У пользователя есть право на удаление: `DELETE /v1/progress` стирает
  его данные с сервера.

## Что уже проверено

Логика валидации подписи протестирована на 5 сценариях: валидная подпись
пропускается, подделка чужим токеном отвергается, подмена user_id ломает
hash, просроченный токен отклоняется, пустой — тоже. См. коммит с worker/.
